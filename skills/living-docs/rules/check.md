# living-docs check & quality checks

## living-docs check — the deterministic instrument

`living-docs check [docs/]` mechanically validates the invariants a machine checks better than
prose: frontmatter/`type`, directory-index membership + root reachability, link resolution,
supersede integrity (including a `superseded_by` link on a record whose status is not Superseded, ADR 0098), Mermaid fences, **unfilled `{{PLACEHOLDER}}` slots and a `description` still the template's placeholder** (a violation — a
scaffold left half-authored fails the gate), and **required sections** (ADR 0064): a live record
missing a section its type requires fails with `missing required section '<name>'`. Retired
records are exempt. *A constraint without an instrument is a vibe* — so
the checkable invariants get a checker. Wire it into the project's quality gate / CI; a docs PR
that fails it does not merge. It does **not** check docs-first mirroring or "one home per fact"
semantics — those have no sound oracle and stay with the reviewer.

It also emits **advisories** — findings that never move the exit code, surfaced as work to
schedule. The text report prints violations first, then one summary line per advisory kind
(`2 SIZE advisories: 0017, 0029`, the first five records then `(+N)`); `--advisories` lists
every advisory in full, and the JSON output always carries them all. The kinds:

- `SIZE` — a decision/execution body past the ~120-line target (aim ~100; research exempt).
- `OWNER` — a record of a type that requires an owner has none (a violation under
  `--require-owner`).
- `HEADING` — a record's title heading disagrees with its frontmatter `title`; `manage fmt`
  aligns it.
- `MOVED-SOURCE` — a record whose linked source path moved.
- `BLOCKED-BY` — every `blocked_by` finding of an issue is advice and never fails `check`: an item that is not a decimal number (a tracker identifier, `ADR 0077`, never validated), a number naming no issue, an issue listing itself, and a cycle of issues waiting on one another (advised once, naming every member).
- `LINK-STYLE` — a link or image written `/`-rooted (`/adr/0007-x.md`); the advisory names the
  relative form to write instead (`../adr/0007-x.md`). It fires whether or not the target exists
  and never moves the exit code.
- `STATUS-VOCABULARY` — a record's status is neither in its type's vocabulary nor Superseded.
- `RECORD-TYPE` — a record in a typed directory declares a different type than the directory's.
- `TIMESTAMP` — a record of a registry type has no timestamp; `living-docs manage fmt` seeds it.
- `PATH-MISSING` — a live record names, in inline code outside a fenced block, a repository path that
  does not exist (`src/gone.rs`, with an optional `:LINE`). A token counts as a path when it holds only
  letters, digits and `_ . / @ + ~ -`, contains a `/`, and its first segment is an entry of the repository
  root (the nearest ancestor of the bundle holding `.git`); only existence is probed. An absolute token
  (`/login`) and a token with a `..` segment are not paths, and neither is one that resolves outside
  the repository (a symlink leaving it); none of them is advised. Without a repository the rule is skipped;
  retired records and index files are not examined.
- `ANCHOR-MISSING` — a local link to a markdown file in the bundle whose `#fragment` matches no heading of that
  file, by GitHub's heading-anchor rule (lowercase, punctuation dropped, spaces as hyphens, `-1`, `-2` for a repeated
  heading); a same-file `#fragment` is judged against the linking file. External links, non-markdown targets,
  links with no fragment and a link to a missing file (already a violation) are not judged; an inline `<a id>`
  is not read.
- `STALE-VIEW` — an architecture view whose generated region is stamped (`<!-- generated by: CMD | inputs: GLOB[, GLOB...] | sha256: HEX -->`)
  and whose recorded hash differs from the current hash of the files its globs match under the repository root (files `.gitignore` excludes are skipped; a symlink counts as its target text); the advisory
  names the view, the opening marker's line and the globs. A malformed stamp or an unsupported glob is advised as a stamp that
  cannot be checked. An unstamped region is never judged, a retired view is, and the marker's command is never run. Without a
  repository the rule is skipped.
- `STATE-MACHINE` (ADR 0102) — in each `stateDiagram` fence of an architecture view with `kind: state`: a state not reachable
  from the root `[*]` (a composite entered directly takes its own `[*]`; entering an inner state also reaches its enclosing composites but not their `[*]`), a state that is not final, has no outgoing transition and
  sits in no composite with one (a state whose only transition is to itself counts as having one; add `X --> [*]` if it is terminal), and a scope with more than one initial transition. Notes
  are ignored; choice, fork and join are plain states. A diagram with concurrent regions (`--`) or no root `[*]` gets one
  "not proved" advisory. Only state views are judged; the exit code stays put.
- `DECISION-TABLE` (ADR 0102) — a table marked `<!-- decision-table -->` or `<!-- decision-table: first -->` under a `###` rule of a
  domain record: a combination of the declared condition values no row covers, two rows with different outcomes on one
  combination (default policy), a row fully shadowed by earlier rows (`first`), a value outside its condition's domain, a
  malformed marker or header, or a table over 4096 combinations ("too large to prove"). An unmarked table is never read; the
  exit code stays put. The grammar is in `read guide domain`.
- `LIVENESS` (`stale-proposed`, ADR 0049, ADR 0079) — an ADR still at its seed status (`Proposed`)
  that an issue already `closed`/`done`/`Superseded` declares it implements: the issue body
  holds `Implements` (any case) followed by a link to the ADR, so the work landed but the record
  never left its birth state. A link from the ADR to an issue is history and never counts.
  Currency has a sound oracle where materiality does not, so the checkable part lives in the
  tool; the exit code stays put.

```bash
living-docs check docs   # check the project's bundle; exit 1 on any violation
```

It is a native Rust binary (correct without shelling out to a hand-rolled markdown/YAML
parser): `serde_yaml` for frontmatter, `pulldown-cmark` for link extraction and resolution
(every link form — inline, titled, angle-bracket, reference-style, images), and a native
directory-index/reachability BFS plus supersede-chain walk for the OKF structural graph.
No host tools to install — install the binary itself via `./install.sh` or
`make cli-install`. `living-docs check --mermaid-only` validates Mermaid fences in-process
via the pure-Rust merman-core parser (ADR 0013) — no Docker, no host tools.

A worked, lint-clean corpus lives in [`examples/linkly/`](../../examples/linkly/) — copy its shapes.

## Quality checks

Before considering a docs change complete. The frontmatter, indexing, link-resolution,
supersede, and placeholder items are enforced by `living-docs check` — run it rather than
eyeballing them; the rest are judgement:

- [ ] Every concept doc opens with OKF frontmatter carrying a non-empty `type`; `status` is in frontmatter, not a body line.
- [ ] Directory listings are `index.md` with no frontmatter (except the bundle-root `docs/index.md` → `okf_version`); cross-links are relative to the linking file (`../adr/0007-x.md`), never `/`-rooted.
- [ ] Every new doc is linked from its directory `index.md` **and** the bundle-root `docs/index.md`.
- [ ] No concept appears in two files (cross-reference instead).
- [ ] No unfilled `{{PLACEHOLDER}}` slot remains in any record, and no `description` is still its template's placeholder sentence.
- [ ] Every live record carries its type's required sections as headings (issue: Scope, Acceptance; ADR: Context, Decision, Consequences; PRD: Problem / Motivation, Non-goals; constitution: Product, Scope Boundaries, Non-negotiables).
- [ ] Superseded ADRs/PRDs carry frontmatter `status: Superseded` + `superseded_by: NNNN`; the superseding record sets `supersedes` and links back.
- [ ] A Superseded or Deprecated record's body opens with its exact CLI-written callout above the heading, and no active record opens with one; `living-docs manage fmt` is the remediation.
- [ ] Every record carries a `timestamp`, and a type that requires an owner has one; a title heading matches the frontmatter title. `living-docs manage fmt` repairs these three (a missing timestamp from the adding commit, a missing owner from git config, the heading from the frontmatter title) and changes no other prose; with no git identity the owner advisory stays until the owner is written by hand.
- [ ] Any structural code change in the same task updated its doc, including its Mermaid diagram(s).
- [ ] Architecture diagrams use Mermaid (in-repo text) and match the code.
- [ ] The constitution is singular (`docs/constitution.md`) — no NNNN prefix, no index entry.
- [ ] Each index file's links all resolve (no dangling references).
- [ ] Docs-first respected: the repo body matches the published tracker/wiki copy.
